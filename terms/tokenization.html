Token 化（斷詞） Tokenization

一句話定義

把文字切成模型能處理的最小單位 token，再轉成整數編號。

白話比喻

就像把一座樂高城堡拆回一顆顆標準積木：模型看不懂「句子」，只認得固定規格的積木（token）和它們的型號（ID）。常見的字會是一整塊大積木，罕見的字則被拆成好幾塊小積木。

運作原理

  1. 建立詞彙表：在大量文本上統計，例如 BPE 會反覆把「最常一起出現的兩個片段」合併成新 token，直到詞彙表達到設定大小（常見 3 萬～20 萬個）。
  2. 切分：輸入文字依詞彙表切成 token 序列，例如「生成式AI」可能被切成「生成 / 式 / AI」。
  3. 轉成 ID：每個 token 查表換成一個整數，模型實際接收的是一串數字。
  4. 加入特殊 token：加上「句首」「句尾」「填充」等特殊記號，讓模型知道邊界。

關鍵公式

"我喜歡 AI" → ["我", "喜歡", " AI"] → [ID₁, ID₂, ID₃]   （示意）

Token 化本身沒有數學公式，它是一個「文字 → 片段 → 整數」的查表流程；實際切法與 ID 取決於各模型的詞彙表。

代表模型與應用

  • BPE（Byte Pair Encoding）（2016）：GPT 系列採用的子詞切分法。
  • WordPiece（2016）：BERT 使用的切分法，與 BPE 類似但合併標準不同。
  • SentencePiece（2018）：直接處理原始字串、不依賴空白斷詞，適合中文與日文，T5、LLaMA 等模型採用。
  • API 計費：各家 LLM API 都以 token 數計算費用與上下文長度。

常見誤解

  • 誤解：1 個 token 就是 1 個字或 1 個英文單字。
    其實：不一定。常見詞可能一個 token，罕見中文字可能被拆成 2～3 個 token；同一段話在不同模型的 token 數也不同。
  • 誤解：模型「看得到」每個字母。
    其實：模型看到的是 token，所以「數某個單字有幾個 r」這類問題對 LLM 反而困難。
